# Model Card — Random Forest Air Quality Prediction Model

## Model Description

This project uses a Random Forest classification model developed using the scikit-learn machine learning library. The model was trained using processed air quality and meteorological measurements collected from monitoring stations and DBRepo-integrated workflows. The primary objective of the model is to classify air quality conditions using pollutant concentrations, environmental measurements, and temporal attributes within a FAIR data science framework.

The model was implemented in Python using the `RandomForestClassifier` algorithm from scikit-learn version 1.4.2. Training and evaluation workflows were executed through Jupyter notebooks included in the repository. The experiment integrates FAIR metadata standards including RO-Crate, FAIR4ML, CodeMeta, and Croissant metadata records.

The trained model artefact is stored in:

`models/model_randomforest_api_v1.pkl`

## Training Data

The model was trained using the processed air quality dataset stored in:

`data/inp_air_quality_processed_v1.csv`

The dataset contains 43,800 records and 25 variables representing pollutant concentrations, meteorological conditions, monitoring station information, and temporal measurements. Variables include PM2.5, PM10, ozone, nitrogen dioxide, sulfur dioxide, temperature, humidity, wind speed, pressure, rainfall, and additional pollutant indicators.

The dataset metadata indicates that the source data is distributed under the CC-BY-4.0 licence:

https://creativecommons.org/licenses/by/4.0/

A dataset DOI will be added after repository and dataset deposition workflows are completed through Zenodo or TUWRD.

## Model Architecture and Hyperparameters

The machine learning algorithm used in this project is `RandomForestClassifier` from scikit-learn version 1.4.2. Random Forest is an ensemble learning method that combines multiple decision trees to improve classification robustness and reduce overfitting. The implementation was executed within Jupyter notebook workflows integrated into the FAIR metadata pipeline.

The model was trained using the following hyperparameters:

| Hyperparameter | Value |
|---|---|
| n_estimators | 100 |
| criterion | gini |
| max_depth | None |
| min_samples_split | 2 |
| min_samples_leaf | 1 |

The training workflow is documented in:

`src/src_air_quality_api_experiment_v1.ipynb`

## Evaluation Results

The model was evaluated using classification metrics generated from the held-out test dataset. Due to class imbalance in the dataset, both macro-average and weighted-average metrics were included during evaluation. The majority of records belonged to the “Good” air quality class, while minority classes such as “Poor” contained significantly fewer examples.

The following evaluation metrics were obtained during testing:

| Metric | Value |
|---|---|
| Accuracy | 0.96 |
| Precision (Macro Avg) | 0.81 |
| Recall (Macro Avg) | 0.56 |
| F1-Score (Macro Avg) | 0.64 |
| Precision (Weighted Avg) | 0.95 |
| Recall (Weighted Avg) | 0.96 |
| F1-Score (Weighted Avg) | 0.95 |

Class-level metrics observed during evaluation included strong performance for the “Good” class but reduced recall and F1-score values for minority classes such as “Moderate” and “Poor.” The evaluation outputs and confusion matrix visualizations are stored in the `outputs/` directory of the repository.

Relevant output files include:

- `outputs/outp_confusion_matrix_api_v1.png`
- `outputs/outp_model_comparison_api_v1.png`
- `outputs/outp_pm25_histogram_api_v1.png`

## Limitations

The training dataset is highly imbalanced, with the majority of observations belonging to the “Good” air quality category. This imbalance affects model performance on minority classes and results in lower recall values for underrepresented conditions. The model therefore performs unevenly across target categories.

The workflow was developed using a specific dataset structure and may not generalize to different geographic regions, sensor infrastructures, or temporal conditions. Environmental data quality can vary significantly depending on station calibration, measurement frequency, and data collection procedures. These factors may introduce hidden biases or inconsistencies in prediction outcomes.

The current implementation does not include advanced fairness analysis, uncertainty estimation, explainability methods, or temporal forecasting mechanisms. Future work may improve robustness through additional validation datasets, rebalancing techniques, and explainable AI approaches.
